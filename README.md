# 今日の一句 — GitHub Pages + GAS 版 セットアップ・デプロイ手順書

会員登録（ニックネーム＋メール登録、仮パスワード発行、初回強制パスワード変更、
パスワード忘れ時の再発行、5回失敗ロック、ニックネーム変更、退会）に対応した版です。

## ファイル構成

```
kyou-no-ikku/
├── index.html    ← フロントエンド（GitHub Pagesで公開。HTML+CSS+JS一体型）
├── Code.gs       ← バックエンド（Google Apps Script。ウェブアプリとしてデプロイ）
└── README.md
```

フロントは **GitHub Pages**、バックエンドAPIは **Google Apps Script** という、
いつもの構成です。`index.html` は `google.script.run` を使わず、`fetch()` で
GASのウェブアプリURLにアクセスします。

---

## 1. Google スプレッドシートを作成する

1. [Google スプレッドシート](https://sheets.google.com) を開き、**新しいスプレッドシート**を作成
2. スプレッドシートの名前は任意（例：「今日の一句DB」）
3. シートは自動作成されるので、そのままでOK（`posts` と `members` の2シートが自動生成されます）

---

## 2. Google Apps Script プロジェクトを作成する

1. スプレッドシートのメニューから `拡張機能` → `Apps Script`
2. 左のファイル一覧の `コード.gs` の中身を**すべて削除**し、`Code.gs` の内容を貼り付けて保存
3. **`index.html` はGAS側には不要です**（GitHub Pagesで配信するため）。もし前バージョンで
   GAS内に `index` という名前のHTMLファイルが残っている場合は削除してかまいません
4. **Gemini APIキーを設定する**（AI評価機能に必須）：
   [Google AI Studio](https://aistudio.google.com/app/apikey) でAPIキーを取得し、
   Apps Scriptエディタの「プロジェクトの設定」（左メニューの歯車アイコン）→
   「スクリプト プロパティ」→ 「スクリプト プロパティを追加」で、
   プロパティ名 `GEMINI_API_KEY` に取得したキーを設定して保存してください。
   ※ 設定しなくても投稿自体は失敗しませんが、AI評価（点数・コメント）は付きません。

---

## 3. GASをウェブアプリとしてデプロイする

1. 右上の **「デプロイ」→「新しいデプロイ」**
2. 歯車アイコン → **「ウェブアプリ」**
3. 設定：

   | 項目 | 設定値 |
   |------|--------|
   | 説明 | 今日の一句 API v2.0（会員機能付き） |
   | 次のユーザーとして実行 | **自分（自分のGoogleアカウント）** |
   | アクセスできるユーザー | **全員** |

4. **「デプロイ」** をクリックし、承認を求められたら許可する
5. 表示された **ウェブアプリURL**（`https://script.google.com/macros/s/.../exec`）をコピー

---

## 4. index.html にAPIのURLを設定する

`index.html` 内の `<script>` タグの先頭付近にある、以下の行を書き換えてください。

```js
const GAS_API_URL = "https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec";
```

`YOUR_DEPLOYMENT_ID` の部分を、手順3でコピーした自分のウェブアプリURLに置き換えます。

---

## 5. GitHub Pages に公開する

1. GitHubリポジトリ `kyou-no-ikku`（任意の名前）を作成
2. `index.html`（手順4でURLを書き換えたもの）をリポジトリ直下にアップロード
3. リポジトリの `Settings` → `Pages` → `Branch` を `main` に設定して保存
4. 公開URL（例：`https://kenken6291.github.io/kyou-no-ikku/`）にアクセスして動作確認

---

## 6. 動作確認

- 公開URLにアクセスし、投稿一覧の読み込み（空でもOK）ができるか確認
- 「新規登録」からニックネーム・メールアドレスを登録 → 自分のメールに仮パスワードが届くか確認
- 仮パスワードでログイン → 初回ログイン時に新しいパスワードの設定を求められるか確認
- ログイン後に「句を詠む」から投稿できるか確認
- 投稿すると数秒後に、句のカードに「✨ AI評価 ◯◯点」と一言コメントが表示されるか確認
  （`GEMINI_API_KEY` が未設定の場合はAI評価が表示されませんが、投稿自体は成功します）
- 「季節別」「年別」ボタンで、投稿が季節・年ごとにグループ分けされ、各グループ内でAI評価の点数が高い順に並ぶか確認
- 以前投稿した句（AI評価が付いていないもの）に「✨ AI評価を取得」ボタンが表示され、押すと評価が付いて以後もずっと表示され続けるか確認（自分の投稿にのみ表示されます）
- 自分の投稿にだけ「編集」「削除」ボタンが表示されるか確認
- ログイン中に「アカウント設定」からニックネームが変更できるか確認
- 「アカウント設定」→「退会する」で、パスワード確認のうえアカウントが削除されるか確認（過去の投稿は残ります）
- スプレッドシートに `posts` シート・`members` シートが自動作成され、データが記録されているか確認
- `members` シートの `passwordHash` `salt` 列が非表示になっていることを確認（パスワードは平文では一切保存されません）

---

## 7. 更新・再デプロイ方法

**GAS（Code.gs）を修正した場合：**

1. `デプロイ` → `デプロイを管理`
2. 鉛筆アイコン（編集）→ バージョンを **「新しいバージョン」** に変更 → `デプロイ`

> ⚠️ 「既存のバージョン」のままだとコードが反映されません
> ⚠️ 再デプロイしてもウェブアプリURL自体は変わりません（`index.html` 側の書き換えは不要）

**index.html を修正した場合：**

GitHubリポジトリの `index.html` を差し替えてコミットするだけでOKです（GitHub Pagesは
数分以内に自動反映されます）。

## セキュリティ設計の解説

### ✅ 実装済みの対策

| 脅威 | 対策 |
|------|------|
| **パスワードの漏洩** | パスワードは平文で保存せず、SHA-256 + ユーザー毎salt + アプリ共通pepper でハッシュ化して保存。pepperはスクリプトプロパティに保管され、コード上にもスプレッドシート上にも現れない |
| **不正ログイン（総当たり）** | 同一メールアドレスでのログイン失敗が5回続くと15分間ロック |
| **なりすまし投稿・不正な編集/削除** | 投稿の作成・編集・削除はログイン必須。編集・削除は「投稿を作成した会員」と「現在ログイン中の会員」が一致する場合のみサーバー側で許可 |
| **セッションの奪取・偽装** | ログイン成功時にサーバーがランダムなセッショントークンを発行し、CacheServiceで6時間のみ有効に管理。トークン自体からはメールアドレスやパスワードは一切推測できない |
| **XSS（クロスサイトスクリプティング）** | サーバー側で全入力をサニタイズ。フロントは `esc()` 関数でHTMLエスケープして描画 |
| **不正な値の注入** | `type`・`generation` は許可リストと照合。文字数・配列長も検証 |
| **会員情報の漏洩** | `passwordHash`・`salt` 列はスプレッドシート上で非表示設定。APIレスポンスにも一切含めない。投稿一覧には会員IDを含めず、`isOwner`（自分の投稿かどうかの真偽値）のみサーバー側で判定して返す |
| **メールアドレスの存在調査（列挙攻撃）** | 「パスワード忘れ」は、登録済みかどうかに関わらず常に同じ応答を返す |
| **クロスオリジン通信** | GitHub Pages（別オリジン）からGASへは `Content-Type: text/plain` で fetch することでCORSプリフライトを回避しつつ、GAS側でJSONとしてパースする、確立された方式を採用 |
| **同時書き込み競合** | 会員登録・座布団加算処理に `LockService` を適用し、同時アクセス時のデータ競合を防止 |
| **なりすまし退会** | 退会には現在のパスワードの入力を必須とし、一致した場合のみアカウントを削除 |
| **Gemini APIキーの漏洩** | `GEMINI_API_KEY` はコードに直接書かず、スクリプトプロパティにのみ保存 |
| **AI評価の障害が本機能を止めない** | Gemini APIの呼び出しに失敗しても例外を投げず、AI評価なしで投稿自体は成功させる設計 |

### ⚠️ 制限事項・注意点

- **セッションの有効期限は6時間**（CacheServiceの上限）です。それを過ぎると再ログインが必要になります
- **完全なパスワードポリシーの強制はしていません**（8文字以上のみ必須）。より厳格にしたい場合は英数字混在などのルールを追加できます
- **メール送信は `MailApp`** を使用しており、Googleアカウントの送信上限（無料の個人アカウントで1日あたり約100通）に注意してください。仮パスワード発行が集中すると上限に達する可能性があります
- スプレッドシートの列非表示はあくまで誤操作防止であり、スプレッドシートの編集権限を持つ人（＝スクリプト所有者本人）からは常に閲覧・編集が可能な点に変わりはありません

## トラブルシューティング

| 症状 | 対処法 |
|------|--------|
| 「読み込みに失敗しました」「通信エラーが発生しました」 | `index.html` 内の `GAS_API_URL` が正しく設定されているか確認。デプロイ時の「アクセスできるユーザー」が「全員」になっているか確認 |
| 投稿・登録しても反映されない | GASを再デプロイ（新しいバージョン）したか確認 |
| 仮パスワードのメールが届かない | 迷惑メールフォルダを確認。Apps Scriptの「実行数」（実行ログ）でMailAppのエラーが出ていないか確認 |
| 編集・削除ボタンが出ない | ログインしていないか、その投稿の投稿者本人でログインしていない可能性があります |
| ログインできない（ロック表示） | 5回失敗すると15分ロックされます。時間を置くか、「パスワードをお忘れですか？」から仮パスワードを再発行してください |
| AI評価（点数・コメント）が表示されない | `GEMINI_API_KEY` がスクリプトプロパティに正しく設定されているか確認。Apps Scriptの実行ログに `Gemini APIエラー` が出ていないか確認してください |
